# Kord Breach — спавны секретных документов

[English](README.md) · **Русский**

Интерактивный справочник по точкам спавна секретных документов: выбираешь
локацию, получаешь карту с иконками документации, клик по иконке открывает
скриншот с описанием, стрелки ← / → листают остальные спавны этой локации.

**Сайт:** https://voctavian.github.io/kord-breach-documents/

171 точка на 12 локациях, 8 типов документации, 173 скриншота. Интерфейс и
описания — русский и английский.

## Страницы

| Страница | Что делает |
| --- | --- |
| `index.html` | выбор локации: превью карты, число спавнов, какие типы документации есть |
| `map.html?map=<id>` | карта с иконками, фильтр по типу документации, просмотрщик скриншотов |
| `editor.html?map=<id>` | правка точек — **только локально**, на сайт не публикуется |

Ссылка на редактор показывается только при открытии с `localhost`, а сама
страница в сборку GitHub Pages не попадает: опубликованный сайт read-only.

## Запуск локально

```
node server.mjs
```

Открыть http://localhost:5173 (порт задаётся через `PORT`). Зависимостей нет —
нужен только Node 18+.

## Редактор

Запусти `node server.mjs` и открой `editor.html`.

- **Поставить точку** — выбери локацию в шапке, слева появится скриншот с
  описанием; кликни по карте в нужном месте. Маркер встанет, редактор сам
  перейдёт к следующей неразмеченной точке.
- **Править описание** — поля «Описание (RU)» и «Описание (EN)» пишутся сразу.
- **Сменить тип документации** — выпадающий список над описанием.
- **Скриншоты** — «+ Скриншот» загружает файлы (jpeg/png/webp, до 12 МБ) в
  `assets/screenshots/`, «Убрать фото» убирает текущий кадр из точки (файл на
  диске остаётся). Если кадров несколько, под основным появляются миниатюры.
- **Новый спавн** — «+ Новый спавн» создаёт пустую точку: заполни описание,
  добавь скриншот, потом кликни по карте.
- **Удалить точку** — «Удалить точку».

Всё сохраняется автоматически (`POST /api/spawns` → `data/spawns.json`), кнопка
«Сохранить» нужна только для ручного сохранения.

Горячие клавиши: `←` / `→` — предыдущая / следующая точка, `Esc` — закрыть
увеличенный скриншот.

> Редактор держит весь список точек в памяти вкладки и при каждом изменении
> перезаписывает `data/spawns.json` целиком. Если файл менялся снаружи (скриптом
> или руками), перезагрузи страницу редактора — иначе следующее действие вернёт
> старую версию.

## Публикация обновлений

Разметил новые точки — публикуй одной командой:

```
node scripts/publish.mjs
```

Она проверяет данные, коммитит, пушит и ждёт, пока обновление доедет до сайта.

| Флаг | Что делает |
| --- | --- |
| `--dry-run` | только проверки и предпросмотр коммита |
| `-m "текст"` | своё сообщение коммита вместо сгенерированного |
| `--all` | закоммитить вообще всё, а не только `data/` и `assets/screenshots/` |
| `--no-wait` | не ждать деплой |
| `--no-changelog` | не добавлять запись в «Что нового» |
| `--changelog-only` | только записать «Что нового» и выйти — чтобы посмотреть попап до пуша |

Перед коммитом проверяется: уникальность id, существование локации и типа
документации, наличие всех файлов скриншотов. Если что-то не так — публикация
отменяется. Отдельно предупреждает про точки без координат, пустые заготовки и
скриншоты, которые ни к одной точке не привязаны.

Сообщение коммита собирается из разницы с предыдущей версией, например
`Обновление спавнов: новых точек: 4, размечено: 4, сдвинуто: 2`.

Если деплой упал, скрипт один раз перезапускает прогон сам. Когда падает и
повтор — почти всегда это перебой на стороне GitHub, смотри
[githubstatus.com](https://www.githubstatus.com/).

В Claude Code то же самое доступно как `/publish`.

## Что нового

При каждой публикации, в которой изменилось видимое посетителю, `publish.mjs`
дописывает запись в `data/changelog.json`: время публикации (поле `at`, местное,
с точностью до минуты) и список точек по локациям, разложенный на «новые» и
«исправления». Точка попадает в «новые», когда впервые становится видна на карте
— неважно, только что создана или наконец получила координаты.

Попап «Что нового» открывается сам, если есть записи, которые посетитель ещё не
закрывал. Закрыл — сам больше не появится до следующей публикации; отметка о
прочтении лежит в `localStorage` под ключом `kord_breach_changelog_v1`.
Непрочитанное показывается развёрнутым, всё остальное — свёрнутыми `<details>`
под заголовком «Прошлые обновления». Пришедшему впервые разворачиваются только
три последних записи, длинные списки сворачиваются в «и ещё N».

История сворачивается по мере старения: обновления текущего месяца лежат
списком, месяцы постарше — папками «Июль 2026», прошлые годы — папкой года, внутри
которой месяцы, внутри которых уже сами обновления. Рядом с заголовком папки —
число записей в ней.

Кнопка «📋 Обновления» рядом с «Угостить кофе» открывает попап в любой момент.
При открытии вручную последняя запись всегда развёрнута, даже если её уже
читали.

Посмотреть попап до пуша:

```
node scripts/publish.mjs --changelog-only
```

Запись пишется в файл, коммита не происходит. Обычный прогон после этого увидит
её и не станет дублировать.

## Данные

| Файл | Содержимое |
| --- | --- |
| `data/spawns.json` | точки: карта, тип документации, описание `caption`/`captionEn`, массив `images`, координаты `x`/`y` в процентах от размера карты |
| `data/maps.json` | 12 локаций: файл карты, тип (`raster`/`svg`), размеры |
| `data/docs.json` | 8 типов документации: название ru/en, иконка, цвет маркера |
| `data/changelog.json` | история обновлений для попапа «Что нового», новое сверху |
| `assets/screenshots/` | скриншоты спавнов |
| `assets/maps/` | карты локаций |
| `documentations/` | иконки типов документации |

Координаты хранятся в процентах, поэтому не зависят от масштаба показа.
`x: null` означает, что точка ещё не размечена — на карте её нет, а в списке она
подсвечена красным. Точки без описания и без скриншотов считаются заготовками и
на сайт не попадают.

## Настройка сервисов

Ключи сторонних сервисов лежат в [js/config.js](js/config.js). Пустое значение —
сервис просто выключен.

**Счётчик онлайна** в шапке — Supabase Realtime Presence. Каждая вкладка держит
вебсокет и объявляет себя в общем канале `kord-breach-online`; число участников
канала и есть онлайн. Своего сервера не нужно, база не задействована.

1. Завести проект на [supabase.com](https://supabase.com) (бесплатный тариф).
2. Project Settings → API → скопировать **Project URL** и **anon public key**.
3. Вписать их в `SUPABASE_URL` и `SUPABASE_ANON_KEY`.

Ограничение бесплатного тарифа — 200 одновременных подключений; при превышении
лишние просто не подключатся, сайт продолжит работать. `anon key` рассчитан на
публикацию в браузере, но держи в этом проекте только Realtime — ни таблиц, ни
файлов. Если однажды заведёшь таблицы, включи RLS, а `service_role` ключ сюда не
клади никогда.

**Приглашение в Discord** — `DISCORD_INVITE`, используется и кнопкой «Фидбэк», и
иконкой в шапке. Текущее приглашение бессрочное; Discord по умолчанию выдаёт
ссылки на 7 дней, так что при замене проверяй срок:

```
curl -s "https://discord.com/api/v10/invites/UErdQwg7ww?with_expiration=true"
```

## Аналитика

Два сервиса, потому что отвечают на разные вопросы.

**GoatCounter** — https://kord-breach-documents.goatcounter.com. Скрипт подключён
в `index.html` и `map.html`, просмотры считаются сами, с локалхоста `count.js`
ничего не отправляет.

**Umami Cloud** — [cloud.umami.is](https://cloud.umami.is), бесплатный Hobby.
Добавлен ради realtime-режима, которого у GoatCounter нет. Website id вписывается
в `UMAMI_WEBSITE_ID` в `js/config.js`.

Дополнительные события шлёт `js/analytics.js`:

| Событие | Когда |
| --- | --- |
| `map-open-<id>` | клик по карточке локации |
| `spawn-view-<id>` | открытие просмотрщика скриншотов (пролистывание стрелками не считается) |
| `lang-switch-<ru\|en>` | переключение языка |
| `coffee-open`, `feedback-open`, `discord-open` | кнопки поддержки и фидбэка |
| `changelog-new-<id>` | попап «Что нового» открылся сам |
| `changelog-open` | попап открыли кнопкой |
| `social-<площадка>` | иконки соцсетей в шапке |

## Скрипты

| Скрипт | Что делает |
| --- | --- |
| `scripts/parse-article.mjs` | разбирает сохранённую копию статьи (`article.html`) в `spawns-raw.json` |
| `scripts/diff-article.mjs` | сравнивает разобранную статью с `data/spawns.json` и показывает, чего не хватает; с `--write` ещё и скачивает |
| `scripts/sync-new-spawns.mjs` | досыпает точки, появившиеся в статье после прошлого разбора, не трогая существующие координаты и правки |
| `scripts/download-screenshots.mjs` | скачивает скриншоты и **создаёт `data/spawns.json` заново** |
| `scripts/download-maps.mjs [id…]` | скачивает карты с вики и обновляет `data/maps.json` |
| `scripts/merge-spawns.mjs` | склейка нескольких скриншотов в одну точку (список в `MERGES`) |
| `scripts/add-en-captions.mjs`, `add-en-captions-2.mjs` | проставляют английские описания |
| `scripts/stage-screenshots.mjs` | добавляет в индекс git только те скриншоты, на которые реально ссылается `data/spawns.json` |
| `scripts/publish.mjs` | проверки → коммит → пуш → ожидание деплоя |

`download-screenshots.mjs` перезаписывает `data/spawns.json` с нулевыми
координатами — перед запуском сделай резервную копию.

Координаты привязаны к конкретному изображению карты: если заменить файл в
`assets/maps/`, размеченные точки этой локации придётся ставить заново.

## Деплой

GitHub Actions ([.github/workflows/deploy.yml](.github/workflows/deploy.yml)) при
пуше в `main` собирает `_site` только из просмотровой части и публикует на GitHub
Pages. Редактор, `server.mjs` и `scripts/` в сборку не попадают — workflow
проверяет это перед загрузкой.
