# Kord Breach — спавны секретных документов

[English](README.md) · **Русский**

Интерактивный справочник по точкам спавна секретных документов: выбираешь
локацию, получаешь карту с иконками документации, клик по иконке открывает
скриншот с описанием, стрелки ← / → листают остальные спавны этой локации.

**Сайт:** https://voctavian.github.io/kord-breach-documents/

171 точка на 12 локациях, 8 типов документации, 173 скриншота. Интерфейс и
описания — русский и английский.

## Страницы

| Страница | Что делает |
| --- | --- |
| `index.html` | выбор локации: превью карты, число спавнов, какие типы документации есть |
| `map.html?map=<id>` | карта с иконками, фильтр по типу документации, просмотрщик скриншотов |
| `editor.html?map=<id>` | правка точек — **только локально**, на сайт не публикуется |
| `survey-editor.html` | опрос и его ответы — **только локально** |

Ссылка на редактор показывается только при открытии с `localhost`, а сама
страница в сборку GitHub Pages не попадает: опубликованный сайт read-only.

## Запуск локально

```
node server.mjs
```

Открыть http://localhost:5173 (порт задаётся через `PORT`). Зависимостей нет —
нужен только Node 18+.

## Редактор

Запусти `node server.mjs` и открой `editor.html`.

- **Поставить точку** — правый клик по карте открывает меню: «Новая точка
  здесь» создаёт точку сразу с координатами, «Переместить сюда» двигает текущую.
  Левая кнопка только таскает карту, случайным кликом координаты не сбить.
- **Править описание** — поля «Описание (RU)» и «Описание (EN)» пишутся сразу.
- **Сменить тип документации** — выпадающий список над описанием.
- **Скриншоты** — «+ Скриншот» загружает файлы (jpeg/png/webp, до 12 МБ) в
  `assets/screenshots/`, «Убрать фото» убирает текущий кадр из точки (файл на
  диске остаётся). Если кадров несколько, под основным появляются миниатюры.
- **Новый спавн** — «+ Новый спавн» создаёт пустую точку без координат: заполни
  описание, добавь скриншот, потом поставь её через меню правой кнопки.
- **Удалить точку** — «Удалить точку».

Всё сохраняется автоматически через полсекунды после правки
(`POST /api/spawns` → `data/spawns.json`). Кнопка «Готово» дописывает
несохранённое и открывает обычную карту этой локации; если запись не прошла,
редактор остаётся на месте и показывает ошибку.

Горячие клавиши: `←` / `→` — предыдущая / следующая точка, `Esc` — закрыть
увеличенный скриншот.

> Редактор держит весь список точек в памяти вкладки и при каждом изменении
> перезаписывает `data/spawns.json` целиком. Если файл менялся снаружи (скриптом
> или руками), перезагрузи страницу редактора — иначе следующее действие вернёт
> старую версию.

## Публикация обновлений

Разметил новые точки или поправил опрос — публикуй одной командой:

```
node scripts/publish.mjs
```

Она проверяет данные, коммитит, пушит и ждёт, пока обновление доедет до сайта.
Опросам отдельной команды не нужно: `data/survey.json` и картинки галерей из
`assets/survey/` уезжают тем же прогоном.

| Флаг | Что делает |
| --- | --- |
| `--dry-run` | только проверки и предпросмотр коммита |
| `-m "текст"` | своё сообщение коммита вместо сгенерированного |
| `--all` | закоммитить вообще всё, а не только `data/`, `assets/screenshots/` и `assets/survey/` |
| `--no-wait` | не ждать деплой |
| `--no-changelog` | не добавлять запись в «Что нового» |
| `--changelog-only` | только записать «Что нового» и выйти — чтобы посмотреть попап до пуша |

Перед коммитом проверяется: уникальность id, существование локации и типа
документации, наличие всех файлов скриншотов. Отдельно — опрос: уникальность
id опросов и вопросов, наличие картинок галерей, отсутствие включённых опросов,
которых нет в списке или которые пусты. Если что-то не так — публикация
отменяется. Предупреждает про точки без координат, пустые заготовки и скриншоты,
которые ни к одной точке не привязаны.

Сообщение коммита собирается из разницы с предыдущей версией и зависит от того,
что менялось:

| Что изменилось | Тема коммита |
| --- | --- |
| только точки | `Обновление спавнов: новых точек: 4, сдвинуто: 2` |
| только опрос | `Опрос: включён «Пара вопросов о карте»` |
| и то и другое | тема про точки, строка про опрос уходит в тело |

Длинная тема обрезается по 72 символам, а целиком перечисление дублируется в
теле — иначе `git log --oneline` режет её сам и некрасиво.

**В коммит попадают не все файлы подряд.** Изменения отслеживаемых файлов берутся
целиком, а вот новый файл из `assets/` добавляется только если на него есть
ссылка из данных. Неприкаянные картинки скрипт перечисляет отдельной строкой
«в коммит не пойдёт, ни к чему не привязано» и оставляет лежать на диске.
Раньше `git add` по каталогу утащил так 1.5 МБ мусора, который потом ездил на
сайт в каждой сборке.

Если деплой упал, скрипт один раз перезапускает прогон сам. Когда падает и
повтор — почти всегда это перебой на стороне GitHub, смотри
[githubstatus.com](https://www.githubstatus.com/).

В Claude Code то же самое доступно как `/publish`.

## Что нового

При каждой публикации, в которой изменилось видимое посетителю, `publish.mjs`
дописывает запись в `data/changelog.json`: время публикации (поле `at`, местное,
с точностью до минуты) и список точек по локациям, разложенный на «новые» и
«исправления». Точка попадает в «новые», когда впервые становится видна на карте
— неважно, только что создана или наконец получила координаты.

Попап «Что нового» открывается сам, если есть записи, которые посетитель ещё не
закрывал. Закрыл — сам больше не появится до следующей публикации; отметка о
прочтении лежит в `localStorage` под ключом `kord_breach_changelog_v1`.
Непрочитанное показывается развёрнутым, всё остальное — свёрнутыми `<details>`
под заголовком «Прошлые обновления». Пришедшему впервые разворачиваются только
три последних записи, длинные списки сворачиваются в «и ещё N».

История сворачивается по мере старения: обновления текущего месяца лежат
списком, месяцы постарше — папками «Июль 2026», прошлые годы — папкой года, внутри
которой месяцы, внутри которых уже сами обновления. Рядом с заголовком папки —
число записей в ней.

Кнопка «📋 Обновления» рядом с «Угостить кофе» открывает попап в любой момент.
При открытии вручную последняя запись всегда развёрнута, даже если её уже
читали.

Посмотреть попап до пуша:

```
node scripts/publish.mjs --changelog-only
```

Запись пишется в файл, коммита не происходит. Обычный прогон после этого увидит
её и не станет дублировать.

## Опрос посетителей

Боковая панель с вопросами: открывается квадратной кнопкой у правого края и
закрывается только крестиком. Сама не выезжает — человек открывает её тогда,
когда сам захочет. Кнопка наполовину утоплена в край экрана и выходит целиком
под курсором (и при обходе с клавиатуры); на тач-экранах, где наводить нечем,
она стоит целиком. Полоска под кнопкой янтарная, пока опрос не пройден, и
зелёная после первого ответа; отвечать можно сколько угодно раз. У непройденного
опроса из левого верхнего угла кнопки свисает красный ярлык «Новый» — он
специально вынесен левее, чтобы оставаться на виду у утопленной кнопки.

Включить можно любое число опросов: их `id` перечислены в `activeIds`, и у
каждого своя кнопка в столбике справа. Открыта при этом всегда не больше одной
панели — следующая закрывает предыдущую. Список пуст — на сайте нет ни кнопок,
ни панелей.

Всё правится локально в `survey-editor.html` (`node server.mjs`, потом ссылка
«Редактор опросов» в шапке — она видна только с localhost). Слева список
опросов: кружок включает и выключает опрос на сайте (их может гореть несколько),
кнопки создают, дублируют и удаляют.
Дублирование копирует опрос вместе с вопросами и картинками, но выдаёт новые
`id` и опросу, и каждому вопросу — иначе ответы двух опросов смешались бы
в выгрузке.

У опроса и у каждого вопроса своя галерея: «+ Картинка» кладёт файл в
`assets/survey/`, на сайте картинки показываются миниатюрами, клик открывает
оригинал. «✕» на миниатюре убирает её из галереи, файл на диске остаётся.

Вкладка «Ответы» показывает ответы выбранного опроса: просмотр, выгрузка в CSV
и удаление спама.

Ответы уходят в таблицу Supabase. Один раз выполнить в SQL Editor проекта:

```sql
create table public.survey_responses (
  id         bigint generated always as identity primary key,
  created_at timestamptz not null default now(),
  survey_id  text not null check (survey_id ~ '^[a-zA-Z0-9._-]{1,64}$'),
  lang       text check (lang in ('ru', 'en')),
  answers    jsonb not null check (pg_column_size(answers) < 8192)
);

alter table public.survey_responses enable row level security;

-- Посетителю можно только писать: без select-политики чужие ответы
-- через anon-ключ не прочитать.
create policy survey_insert_anon on public.survey_responses
  for insert to anon with check (true);
```

Вставка обязана идти с заголовком `Prefer: return=minimal` — иначе PostgREST
попробует вернуть вставленную строку, упрётся в отсутствие select-политики и
ответит 401.

Читает ответы локальный сервер по ключу `service_role` из `.env.local`
(шаблон — `.env.local.example`). Этот ключ обходит RLS целиком, поэтому файл
лежит в `.gitignore`, а **в `js/config.js` его класть нельзя** — тот уезжает в
браузер. Без файла сайт работает как обычно, только вкладка «Ответы» скажет,
чего не хватает.

Ограничения на размер `answers` и формат `survey_id` стоят в самой таблице:
anon-ключ публичный, и залить им в базу мусор произвольного размера не должно
получаться. От спама это не спасает полностью — чистится кнопкой удаления в
редакторе.

## Данные

| Файл | Содержимое |
| --- | --- |
| `data/spawns.json` | точки: карта, тип документации, описание `caption`/`captionEn`, массив `images`, координаты `x`/`y` в процентах от размера карты |
| `data/maps.json` | 12 локаций: файл карты, тип (`raster`/`svg`), размеры |
| `data/docs.json` | 8 типов документации: название ru/en, иконка, цвет маркера |
| `data/changelog.json` | история обновлений для попапа «Что нового», новое сверху |
| `data/survey.json` | опросы: список и `activeIds` тех, что показываются |
| `assets/survey/` | картинки галерей опроса и вопросов |
| `assets/screenshots/` | скриншоты спавнов |
| `assets/maps/` | карты локаций |
| `documentations/` | иконки типов документации |

Координаты хранятся в процентах, поэтому не зависят от масштаба показа.
`x: null` означает, что точка ещё не размечена — на карте её нет, а в списке она
подсвечена красным. Точки без описания и без скриншотов считаются заготовками и
на сайт не попадают.

## Настройка сервисов

Ключи сторонних сервисов лежат в [js/config.js](js/config.js). Пустое значение —
сервис просто выключен.

**Supabase** нужен опросу: ответы уходят в таблицу `survey_responses` (её
разметка и политики — в разделе «Опросы» выше).

1. Завести проект на [supabase.com](https://supabase.com) (бесплатный тариф).
2. Project Settings → API → скопировать **Project URL** и **anon public key**.
3. Вписать их в `SUPABASE_URL` и `SUPABASE_ANON_KEY`.

`anon key` рассчитан на публикацию в браузере и уезжает на сайт вместе с
остальным кодом — защищает не он, а RLS на таблице, поэтому политику «только
вставка» отключать нельзя. `service_role` ключ сюда не клади никогда: ему место
только в `.env.local`.

**Приглашение в Discord** — `DISCORD_INVITE`, используется и кнопкой «Фидбэк», и
иконкой в шапке. Текущее приглашение бессрочное; Discord по умолчанию выдаёт
ссылки на 7 дней, так что при замене проверяй срок:

```
curl -s "https://discord.com/api/v10/invites/UErdQwg7ww?with_expiration=true"
```

## Вход и роли

Google и Discord через Supabase Auth. Схема — [supabase/schema.sql](supabase/schema.sql),
скрипт идемпотентный, выполняется целиком в SQL Editor.

Роли лежат в таблице `user_roles` (`admin`, `subscriber`), а не колонкой в
профиле: роли совмещаются, а у подписки есть срок. Свои роли клиент читает через
RPC `my_roles()`.

**Первый админ выдаётся руками** — автоматики «первый вошедший становится
админом» нет намеренно, это гонка и дыра:

1. Один раз войти на сайте, триггер создаст строку в `profiles`.
2. `insert into public.user_roles (user_id, role) select id, 'admin' from public.profiles where email = '…';`

Дальше роли раздаются в админке. Снять роль с последнего админа не даст триггер
`user_roles_keep_last_admin` — возвращать пришлось бы через SQL Editor.

**Ролей в JWT нет намеренно.** Custom Access Token Hook сэкономил бы запрос, но
сломанный хук роняет вход сразу для всех, а снятая роль продолжала бы работать до
часа, пока не обновится токен. При двух админах выигрыш нулевой.

**Что настраивается в дашбордах.** Redirect URI в Google Cloud Console и Discord
Developer Portal — не сайт, а `<SUPABASE_URL>/auth/v1/callback`. В Supabase →
URL Configuration: Site URL `https://voctavian.github.io/kord-breach-documents/`,
Additional — он же с `/**` и `http://localhost:5173/**`. Скоупы задаются в коде
(`PROVIDERS` в [js/auth.js](js/auth.js)), поля для них в дашборде нет.

Сайт лежит в подпапке, поэтому `location.origin` указывает на чужой корень —
`js/auth.js` везде считает адрес через `new URL('.', location.href)`. Если вписать
origin в настройки Supabase, после входа человека выкинет на 404 GitHub.

Один человек, вошедший и через Google, и через Discord, окажется одним
пользователем только при совпадающем подтверждённом e-mail. Разные почты — два
аккаунта, роль придётся выдать дважды.

## Админка

`admin.html` публикуется и доступна по адресу сайта, но без роли `admin` пишет
«нет доступа» и данных не отдаёт: доступ режет RLS, а проверка в клиенте нужна
лишь чтобы не рисовать бесполезный интерфейс.

| Раздел | Что делает |
| --- | --- |
| Юзеры | выдача ролей `admin` и `subscriber` |
| Опросы | какие опросы показывать (**без деплоя**), просмотр и удаление ответов, выгрузка CSV |
| Спавны | открывает редактор нужной локации |

Тексты опросов остаются в `data/survey.json` и правятся локально в
`survey-editor.html`: это контент, у него история в git и он работает офлайн. В
Supabase живёт только список включённых (`site_settings.survey_active_ids`),
потому что срочная операция — включить или выключить опрос, а не переписать
вопрос. Если Supabase недоступен, `js/survey.js` откатывается на `activeIds` из
файла.

## Правка точек с сайта

Редактор работает в двух режимах, и решает это [js/store.js](js/store.js).

**Локально** он пишет прямо на диск через `server.mjs`, автосохранение через
500 мс после каждой правки — как и было.

**На сайте** диска нет, и сохранить означает закоммитить. Автосохранение
превратилось бы в коммит и прогон деплоя на каждое движение маркера, поэтому
правки копятся в черновике (`localStorage`) и уезжают в репозиторий одним
коммитом по кнопке **«Опубликовать»**. Сайт обновится, когда пройдёт деплой, —
через 1–2 минуты.

Скриншоты, добавленные до публикации, живут в памяти вкладки и показываются через
`objectURL`, но путь им присваивается сразу и считается тем же хешем, что и в
`server.mjs`, — файл, добавленный с телефона и с компьютера, не задвоится. Из
этого же следует, что **неопубликованный черновик не переживёт перезагрузку
вкладки вместе с картинками**; редактор предупреждает об этом в `beforeunload`.

### Edge Function `commit`

[supabase/functions/commit/index.ts](supabase/functions/commit/index.ts) пишет
файлы в репозиторий через GitHub Git Data API — данные и картинки одним коммитом,
чтобы сайт ни на миг не ссылался на несуществующий файл.

Роль вызывающего функция спрашивает у самой базы (`rpc/my_roles`) его же токеном
и отказывает всем, у кого нет `admin`. Так правило «кто может писать» остаётся в
одном месте — в RLS, — и service-ключ функции не нужен вовсе. Пути ограничены
каталогами `data/` и `assets/`.

**Выкатка без CLI:** Dashboard → Edge Functions → Deploy a new function →
*Via Editor*, имя `commit`, вставить файл, Deploy.

Секреты — Project Settings → Edge Functions → Secrets:

| Секрет | Значение |
| --- | --- |
| `GITHUB_TOKEN` | fine-grained токен, только этот репозиторий, **Contents: read and write** |
| `GITHUB_REPO` | `VOctavian/kord-breach-documents` |
| `GITHUB_BRANCH` | необязательно, по умолчанию `main` |

> Источник правды для функции — этот репозиторий. В редакторе дашборда **нет
> истории версий**: правка, сделанная там и не перенесённая сюда, пропадёт
> бесследно.

Если кто-то запушил, пока ты правил, функция ответит `409` вместо перезаписи —
перезагрузи редактор и повтори правку.

## Реклама

Рекламных блоков пока нет — [js/ads.js](js/ads.js) это точка расширения.
`adsEnabled()` совмещает рубильник `site_settings.ads_enabled` с ролями:
подписчик и админ рекламы не видят. `mountAds()` вешает на `<body>` класс
`no-ads`, чтобы будущие плейсхолдеры схлопывались чистым CSS.

> имеет, но крутить рекламу на этих картах — нарушение: либо менять карты, либо
> оставить подписку перком без рекламы.

## Аналитика

Два сервиса, потому что отвечают на разные вопросы.

**GoatCounter** — https://kord-breach-documents.goatcounter.com. Скрипт подключён
в `index.html` и `map.html`, просмотры считаются сами, с локалхоста `count.js`
ничего не отправляет.

**Umami Cloud** — [cloud.umami.is](https://cloud.umami.is), бесплатный Hobby.
Добавлен ради realtime-режима, которого у GoatCounter нет. Website id вписывается
в `UMAMI_WEBSITE_ID` в `js/config.js`.

Дополнительные события шлёт `js/analytics.js`:

| Событие | Когда |
| --- | --- |
| `map-open-<id>` | клик по карточке локации |
| `spawn-view-<id>` | открытие просмотрщика скриншотов (пролистывание стрелками не считается) |
| `lang-switch-<ru\|en>` | переключение языка |
| `coffee-open`, `feedback-open`, `discord-open` | кнопки поддержки и фидбэка |
| `changelog-new-<id>` | попап «Что нового» открылся сам |
| `changelog-open` | попап открыли кнопкой |
| `author-open` | клик по логотипу в шапке |
| `survey-open` | опрос открыли кнопкой |
| `survey-submit` | ответ успешно записан |
| `project-<id>` | переход в другой проект автора |
| `social-<площадка>` | иконки соцсетей в шапке |

## Скрипты

| Скрипт | Что делает |
| --- | --- |
| `scripts/parse-article.mjs` | разбирает сохранённую копию статьи (`article.html`) в `spawns-raw.json` |
| `scripts/diff-article.mjs` | сравнивает разобранную статью с `data/spawns.json` и показывает, чего не хватает; с `--write` ещё и скачивает |
| `scripts/sync-new-spawns.mjs` | досыпает точки, появившиеся в статье после прошлого разбора, не трогая существующие координаты и правки |
| `scripts/download-screenshots.mjs` | скачивает скриншоты и **создаёт `data/spawns.json` заново** |
| `scripts/download-maps.mjs [id…]` | скачивает карты с вики и обновляет `data/maps.json` |
| `scripts/merge-spawns.mjs` | склейка нескольких скриншотов в одну точку (список в `MERGES`) |
| `scripts/add-en-captions.mjs`, `add-en-captions-2.mjs` | проставляют английские описания |
| `scripts/stage-screenshots.mjs` | добавляет в индекс git только те скриншоты, на которые реально ссылается `data/spawns.json` |
| `scripts/publish.mjs` | проверки → коммит → пуш → ожидание деплоя |

`download-screenshots.mjs` перезаписывает `data/spawns.json` с нулевыми
координатами — перед запуском сделай резервную копию.

Координаты привязаны к конкретному изображению карты: если заменить файл в
`assets/maps/`, размеченные точки этой локации придётся ставить заново.

## Деплой

GitHub Actions ([.github/workflows/deploy.yml](.github/workflows/deploy.yml)) при
пуше в `main` собирает `_site` только из просмотровой части и публикует на GitHub
Pages. Редактор, `server.mjs` и `scripts/` в сборку не попадают — workflow
проверяет это перед загрузкой.
